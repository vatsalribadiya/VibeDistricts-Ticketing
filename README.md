## Run it on a phone

1. Install Node.js 20 or newer on a Mac or Windows computer.
2. From this folder run `npm install`.
3. Run `npm start`.
4. Install **Expo Go** on the iPhone or Android phone.
5. Scan the QR code shown by Expo.
6. Open an event, tap **Buy Tickets**, complete the labeled demo checkout, then open **My Tickets**.
7. In **Profile**, open the door scanner. Use a second device to scan the QR, or tap the simulator control to test check-in on one phone.

The iOS simulator requires macOS and Xcode. Android can use Expo Go on a phone or Android Studio on macOS/Windows.

## Phase two backend foundation

The repository now includes a Supabase migration for profiles, events, backend-enforced admin/staff/customer roles, granular staff permissions, event assignments, Row Level Security, and audit logs. Follow `docs/SUPABASE_SETUP.md` to create and link the project. Mobile authentication will be connected after the migration is applied and the public project URL and anonymous key are configured locally.

The mobile app now uses Supabase email and password authentication, encrypted session storage, automatic profile loading, sign out, and role-aware scanner access. New users always begin as customers; admin and staff access comes only from database-backed assignments.

Administrators also receive a protected People and Access tab for customer-to-staff role assignment, account suspension, and granular staff permission management. The screen relies on database Row Level Security rather than UI-only access checks.

## Suggested production architecture

- Mobile: React Native + Expo
- API/database/auth: Supabase or Firebase
- Billing: Stripe subscriptions for physical-event membership
- QR security: short-lived signed token generated by the backend
- Admin: secure web dashboard for events, capacity, guest lists, and scans

## Important

The purchase flow is intentionally marked as a pilot demo: it issues local ticket passes but does not charge a payment card. The patterned pass shown in this version is a visual placeholder, not a production-scannable QR code. Ticket and scan data currently live on one device, so two separate phones will not share check-in state. Do not use the local tokens for public admission until the backend, Stripe, staff authentication, and server-side QR validation are connected.
